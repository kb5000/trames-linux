## Failures resolved

The old X11 pixel probe searched only root-window children. A real Xwayland
window manager reparents clients beneath frame windows, so lookup failed after
the renderer completed 16 frames. The probe now searches recursively and
tolerates a disappearing window. Pixel geometry/color checks remain strict;
both the GPU desktop and software reference pass. Production code is unchanged.

The first controller expected vkcube's selection message on stdout; it is on
stderr. The corrected check requires zero exit and the actual Venus name in the
retained streams. Its initial [1/3 record](gpu-vm-20261125/gpu-acceptance-v1/results.json)
remains separate from corrected and post-restart **3/3** runs.

The minimal image did not discover its first USB configuration disk. Presenting
the same read-only NoCloud seed through VirtIO completed SSH/user/network setup.
The desktop uses seatd to manage the display from its dedicated service.

An early test used UTM's default immediate power-off, losing two freshly written
helper/configuration files. Both were restored. Final durability verification
uses normal shutdown: the boot log has a clean ext4 mount, both files retain
contents, and all GPU cases pass. The original VM disk was not stopped or copied.

## Whole-machine disk scope

Initial directory statistics showed development about 255 GiB, temporary files
57 GiB, application data 45 GiB, and device/simulator data 17 GiB. APFS shared
extents can appear repeatedly in `du`; actual reclamation uses volume free bytes.

Fourteen old isolated Rust build profiles plus unused SwiftPM, Steam UI and
Homebrew download caches were removed, recovering **41.94 GiB**. Sources, logs,
the current CPU build cache, existing VM, games, application environments and
device/simulator data were retained. Exact paths and measurements are in the
[build-cache record](gpu-vm-20261125/cleanup.json) and
[general-cache record](gpu-vm-20261125/general-caches.json).

UTM's 290.6 MiB official installer passed the published SHA-256, Apple signature
and notarization checks. Its [receipt](gpu-vm-20261125/install-receipt.json) is
retained after deleting the installer. The 16 GiB sparse disk had about 1.8 GiB
allocated blocks at the recorded checkpoint, sharing its base on APFS. After
installation and guest setup, about **48 GiB** remained available. The
[timestamped final state](gpu-vm-20261125/final-state.json) records exact bytes.
QEMU debug logs are off and guest journals are bounded.

These checks establish the declared Venus/Metal workflows. Complete Vulkan
conformance, physical Linux GPU drivers, codecs, performance and combined KVM
qualification remain separate.
