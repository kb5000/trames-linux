# HiDPI and multiple native outputs — 2026-11-27

Both Linux desktop frontends now import actual monitor identities and geometry.
Wayland relays output enter/leave, integer and per-surface fractional density;
X11 imports RandR monitors, session DPI and optional per-monitor overrides.
Logical window/configure/input/IME geometry stays separate from native pixels.
SHM and Vulkan use the same physical-size conversion, including 125% and 150%.
See the [usage and boundaries](../architecture/desktop.md#hidpi-and-multiple-outputs).

The independent C peer renders alternating one-pixel columns into correctly
scaled buffers. Original grim screenshots confirm sharp runs at 1x, 125%, 150%
and 2x on both native Wayland renderers. XCB reads verify X11 native dimensions,
full-width alternating columns and scaled ICCCM minimum/maximum hints. Native
input reaches `(120,80)` in guest logical coordinates at 125%. The scenarios also
change output density live, migrate windows, request fullscreen on the other output and verify the native
compositor tree, rotate
an output, unplug/reinsert it and delete an X11 virtual monitor. Same-density
identities, negative logical positions, subsurface inheritance, duplicate
fractional addon errors and retired output lifetimes have independent wire tests.

Sway 1.9 can retain an old fractional-scale hint on output disable. The reference
case records that behavior; it does not assert a new 1x hint for that transition.
Trames additionally falls back to the window's current output membership when
there is no fresh hint after migration or density change. Unrelated output
changes preserve an existing valid per-surface preference. Xserver monitor edits
also require root ConfigureNotify, alongside RandR notifications; this is handled
without polling. See the upstream [Xserver monitor implementation](https://raw.githubusercontent.com/mirror/xserver/master/randr/rrmonitor.c),
[fractional-scale contract](https://raw.githubusercontent.com/wayland-mirror/wayland-protocols/main/staging/fractional-scale/fractional-scale-v1.xml)
and [xdg-output contract](https://raw.githubusercontent.com/wayland-mirror/wayland-protocols/main/unstable/xdg-output/xdg-output-unstable-v1.xml).

X11 per-monitor UI density has no single host setting; explicit
`TRAMES_DESKTOP_OUTPUT_SCALES` overrides are supported. Fullscreen targeting via
EWMH depends on the native WM and matching Xinerama indices; the manual Xvfb
monitor layout does not qualify that matching-screen path. Legacy applications
that supply low-resolution buffers can still be enlarged. The acceptance uses
software displays and Mesa's software Vulkan driver, and does not qualify a
physical GPU, physical monitor cables or AMD64 KVM execution.
