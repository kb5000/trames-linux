# Linux PCM software and KVM validation — 2026-11-25

Runtime: `5b12cc9e69ff12f7eac6d0b3bb78f5a5218e38da`. Product source is the commit
introducing this record. CLI remains `078cc9e21ceafd79f631c74bc2f52083d6282a09`.

The existing Lima/VZ nested KVM VM runs ARM64 Linux 7.0.0-43-generic with a real
4096-byte host page. It has libasound 1.2.11 and development headers, but no PCM
soundcard. These results do not claim physical playback/capture or bare-metal
latency. GPU/video and A/V timing acceptance remain outstanding.

## Passed

- Compile-time ALSA oracle: all 40 actual Rust FFI signatures and used constants
  compiled against native public headers. Checks do not enter execution paths.
- ARM64 Linux strict all-target/all-feature clippy for audio/VFS/session and
  1,049 module tests (2 audio, 12 session, 1,035 VFS), with one existing VFS ignore.
- Software audio integration: S16 file PCM bytes, FLOAT null PCM, exact geometry
  rejection, nonblocking capture, timerfd notification filtering/rearm, patterned
  capture samples, start/pause/resume/drop/prepare and monotonic reset, multiple
  streams on one original eventfd, guest FD close/reuse and native FD retirement.
- Injected ALSA poll errors EPIPE/ESTRPIPE/ENODEV reach subsequent status/transfer;
  prepare clears the latch and XRUN counting occurs once. This validates error
  plumbing, not real hardware suspend/unplug recovery.
- Native vs KVM original ALSA client: playback/capture on both SMCCC and MMIO;
  960 frames per case, native-equivalent output, exact playback file bytes.
  No binary/loaded syscall rewriting. Capabilities remain disabled by default.
- Linux product all-target clippy and all workspace tests on Linux and macOS;
  KVM-dependent cases stay explicitly ignored in ordinary unit jobs.
- Apple compatibility: strict affected-module clippy, audio/session/VFS unit
  tests; Mac workspace check and 32 product unit tests (26 hardware ignores),
  plus 5 HVF library tests (56 hardware ignores). iOS ARM64 FFI cross-check passed
  with the installed Xcode SDK. No physical Apple audio capture was attempted.

The macOS sandbox initially denied local socket binds in 14 existing VFS tests
and one CLI test. Those failures were rerun outside the sandbox and passed;
unaffected passing tests were reused. The iOS check was rerun with the installed
full Xcode developer directory after the default CommandLineTools lacked the SDK.

## Reproduction

Install `libasound2-dev` (tests only), use the pinned toolchain, then run:

```sh
python3 runtime/scripts/check-alsa-abi.py
cargo test --manifest-path runtime/Cargo.toml -p trames-audio --lib --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo build --workspace --locked
TRAMES_BINARY=target/debug/trames python3 scripts/validate-audio.py
```

The last command requires ARM64/4 KiB/KVM and runs both transports. It builds an
isolated guest rootfs, native/guest ALSA configurations, the original guest PCM
plugin, a timerfd-backed test PCM and one common ALSA client. Machine-readable
[results](audio-20261125-results.json) are checked in; generated samples/binaries
stay under the validation output directory.
