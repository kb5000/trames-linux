SHM scenes in native X11 windows and routes keyboard, pointer, wheel and focus
through the existing input API. Actual KVM, independent server-pixel probes,
original GUI terminals and persistent-store cold reopen pass. This qualifies a
software desktop; accelerated graphics/media and full desktop-shell behavior
remain separate gates.

## Defects closed and setup corrections

- Direct host-rootfs sockets: session-private `/run/user/0` and `/tmp` tmpfs keep
  virtual IPC and X11 locks out of HostFS, including repeated/cold startup.
- Xwayland SDK installation: the existing importer addressed private storage,
  failing through HostFS/chroot. Shared namespace-aware SDK staging is reused,
  with executable permissions set before publication and identical inode reuse.
- XCB buffered events: reply waits can hide queued events from descriptor
  readiness. Retain one pending event and latch the original host wake.
- GUI PTYs: the compatibility `/dev/pts` bind lacks `pts/ptmx`; desktop sessions
  now mount the existing real devpts implementation before guest startup.
- Acceptance setup: use a static guest launcher for the existing installer ABI,
  include original Weston themes/cursors, and follow the terminal's actual
  dynamic window title. Missing themes caused the original client to fault;
  missing devpts caused its subsequent `forkpty` failure. Neither is relabeled
  as a successful application run. Earlier [diagnostics](desktop-20261126/diagnostics)
  remain separate from final passes.
