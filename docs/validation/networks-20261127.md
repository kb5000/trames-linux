# Linux named networks and host publications — 2026-11-27

Linux now manages named private IP networks, connects independent named
environment workers, and publishes explicitly authorized host TCP/UDP ports.
The Mac cold registry moved into shared `trames-distro::networks::Networks`;
Mac retains its manager listing and live controls through a thin adapter.
See the [usage guide](../guides/environments.md).

`network create/ls/inspect/remove` and `env publish/unpublish/grant` configure the
next boot. IDs are bound to registered environment UUIDs and survive rename and
restart. Network removal excludes running members, including the first-start
allocation race. Configuration remains transactional. Host port requests are
intersected with UUID-bound host grants before startup.

The implementation reuses Runtime's framed Unix-stream fabric, IP stack, native
sockets and original descriptor readiness. No coordinator, packet pump thread,
service process or polling bus is added. KVM remains a CPU/MMU executor; original
application instructions are unchanged. Platform choices use target cfg, and
cold profile checks introduce no CPU execution-loop checks.

The native POSIX fixture is calibrated against actual host IPv4/IPv6 TCP/UDP
before KVM execution. The matrix exercises cross-process peers, live positive
controls for cross-network rejection, private loopback, same-port reuse, stable
addresses, libc DNS via the standard managed resolver, controlled outbound NAT
and internal-network denial. Actual host clients verify TCP binary full duplex
(2 MiB), TCP half close, zero-length/50 KiB fragmented UDP, IPv6 and wildcard
host bindings. It also checks partial-start rollback, occupied native ports,
grant/request denial and stop/restart release/reuse. Named host mode shares the
actual native socket space.

One-second idle observations in all four cohorts consumed 0.0 process CPU
seconds. This is a regression observation, not a throughput, latency or
host-equivalent performance claim. CPU/4 KiB/graphics implementations did not
change and their previous acceptance is reused.

## Findings fixed

- Explicit host publications used the outbound guest socket policy, incorrectly
  denying wildcard or nonloopback addresses. Granted host bind operations now
  use the native host policy; ordinary outbound guest policy remains separate.
- The standard resolver address `169.254.0.53` was absent from the fabric gateway
  admission rules. Both IP routing and cross-process Ethernet admission now
  recognize it, including internal networks. Regression tests attach a real
  transport rather than testing only local fabric nodes.
- An internal network's raw IP path could miss the wire NAT choice. The common
  route admission now applies it consistently.
- TCP publication restart encountered native TIME_WAIT. Listener SO_REUSEADDR
  permits normal restart; occupied listeners still reject conflicting startup.
- Host option parsing now stops at the guest program, preserving literal guest
  arguments such as `--publish` without requiring an explicit separator.

## Docker service gap and next iteration

The new manual `scripts/validate-network-services.py` probe exposed an original
runc bootstrap failure **before a container serves HTTP**. Real systemd boots,
Docker/containerd start with default runc/overlay2, and image import succeeds;
container creation fails with an init bootstrap pipe reset/broken pipe.

[Raw diagnostics](networks-20261127/docker-diagnostics) retain separate
systemd/bridge, shell/bridge and shell/host attempts. The same shell/host failure
also reproduces on the previous frozen environment runner
`1c023b788bc3bbfb04cffaad162e000739744ebd376b1b1090f85d677a18c314`.
This is a previously uncovered managed-environment compatibility gap, rather
than evidence of a new bridge regression. Earlier standalone Docker lifecycle
passes are not relabeled as named-environment passes. Docker-to-host publication
is **not accepted** by this record. No fallback to crun, reduced GOMAXPROCS,
modified application code or expected-failure pass was used.

The next priority is to isolate private-store/exec/lifecycle differences from
the accepted standalone Docker path, fix runc bootstrap, then require original
container HTTP and stop/restart across both transports. Follow with environment
name DNS and host login/service integration. Linux GUI work remains deferred.

CI checks cold network configuration on all build hosts. The existing KVM
workflow runs the full named-network matrix. Service-image probes remain a local
manual command; no caller-supplied rootfs is executed by privileged CI.
