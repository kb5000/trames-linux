## Corrected behavior

Requests carry per-field generations, preserving the ordering of distinct
operations without inventing an unrelated unset-fullscreen on unmaximize.
An older native reply cannot erase a newer, undispatched guest request.
Requested and confirmed states stay separate, and actual host geometry controls
native configure replies. A zero-sized Wayland restore suggestion retains the
last confirmed floating content size. Parent cycles are rejected.

The native Wayland frontend acknowledges toplevel state/size together at its
following xdg-surface configure. Every subsequent native commit already uses
the confirmed geometry, including while original Xwayland is still preparing
its new buffer. Guest confirmation and later state requests follow that native
frame commit, driven by the existing frame readiness. This prevents a rapid
unset from arriving before the host applies its preceding maximized commit.
CSD extents remain distinct from content geometry. X11 queries
current geometry rather than pairing old ConfigureNotify payloads with newer
property replies, and waits for guest buffers to reach a host resize before
accepting another app-initiated size. This prevents stale guest frames from
rewriting the window manager's saved restore dimensions.

Interactive operations use the real native press: X11 root coordinates/time
or the host Wayland seat/serial. The host consumes the physical release while
moving/resizing, so the Wayland frontend ends the guest implicit grab when
handing it off. Consecutive gestures remain usable. Native parent proxies and
transient properties update without requiring a new guest frame. Keyboard
focus follows native `wl_keyboard.enter/leave`, independently of xdg decoration
activation, so stale activated configures cannot undo a real focus departure.

The protocol contracts are documented by
[EWMH window properties](https://specifications.freedesktop.org/wm/latest/ar01s05.html)
and the original [xdg-shell protocol](https://raw.githubusercontent.com/wayland-mirror/wayland-protocols/main/stable/xdg-shell/xdg-shell.xml).
The native references preserve each window manager's actual size constraints
and task-switch behavior. No CPU instruction rewriting, CPU hot-path ABI
checks, new coordinator/service thread or polling timer is introduced.

protocols, including XCB XTEST and libxkbcommon-x11. Reuse the existing desktop
rootfs/static Xwayland launcher and unchanged source-checked guest CLI.

```sh
python3 scripts/validate-windows.py --unit-binary UNIT --runner TRAMES \
  --receipt BUILD_RECEIPT --rootfs DESKTOP_ROOTFS --launcher LAUNCHER --output NEW_OUT
```

follow-up audit for the current pin. The [offline audit](windows-20261127/audit.py) verifies archive hashes, exact
case identities, native measurements, source manifests and binary/pin identities.

controlled by reusing the existing VM/build cache and removing this batch's
intermediate matrices after freezing final evidence.
